# Data dictionary

The ingestion and analysis code is schema-aware: the names below describe expected concepts, not a guarantee that the trainer file has these exact headers. Inspect a supplied CSV and verify the selected mapping before interpreting results. Profiling API output suppresses sensitive per-record values.

## Customers dataset

| Concept | Common source names | Meaning / use |
|---|---|---|
| Customer key | `customer_id`, `customerId`, similar identifier | Stable customer reference; retained separately from model features. |
| City | `city`, `location` | City standardization and city counts when present. |
| Gender | `gender`, `sex` | Normalized to Male, Female, or Unknown when detected. |
| Signup date | `signup_date`, `registration_date`, similar date field | Date range and signup trend where a valid date column exists. |

## Orders dataset

| Concept | Common source names | Meaning / use |
|---|---|---|
| Order key | `order_id`, `orderId` | Distinct order counting and optional database key. |
| Customer reference | `customer_id`, `customerId` | Relationship to customer data when supported by source keys. |
| Order date | `order_date`, `created_at`, similar date field | Recency and date-based trend. |
| Amount | `order_amount`, `amount`, `total`, similar numeric field | Monetary RFM and value summaries when valid. |
| Status | `order_status`, `status` | Completed-order filter; accepted completed values are configurable. |

## Tickets dataset

| Concept | Common source names | Meaning / use |
|---|---|---|
| Ticket key | `ticket_id`, `ticketId` | Optional unique ticket reference; avoid returning it unnecessarily. |
| Customer/order reference | `customer_id`, `order_id` | Routing context only when needed; protect in model prompts and public responses. |
| Ticket text | `ticket_text`, `message`, `description` | Validated and masked before model-facing use; raw text is not returned by default. |
| Created date | `created_at`, `ticket_date` | Ticket volume trends if parseable. |
| Ticket status | `ticket_status`, `status` | Distribution summaries if present. |
| Category | `category`, `ticket_category` | Used if supplied; otherwise classification output is generated by the guarded pipeline. |

## Derived customer features

| Feature | Definition |
|---|---|
| Recency | Days between configured analysis reference date and the latest valid completed order. |
| Frequency | Number of distinct completed orders per customer. |
| Monetary | Sum of valid amounts for completed orders. |
| Cluster | K-Means cluster identifier based on scaled RFM features. |
| Segment | Descriptive name assigned from observed cluster RFM profile, if supported. |
| Churn risk | Configurable inactivity heuristic, not a learned probability. |

## Data handling rules

The cleaner preserves source files, records operations, and follows a configurable strategy. Missing values may remain missing unless a configured rule applies. Outliers are detected and reported separately from impossible/invalid values. Review [methodology](methodology.md) and the generated cleaning audit before downstream interpretation.
