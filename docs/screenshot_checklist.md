# Screenshot and evidence checklist

Capture screenshots locally after starting the services. No screenshots are fabricated or bundled with this repository. Use the actual UI and redact any real personal information before sharing.

- [ ] **Dashboard overview:** show the actual overview and its data availability state. Do not fill missing values with invented metrics.
- [ ] **Data Quality:** show profile/cleaning page; label any empty state or use only clearly identified test fixtures.
- [ ] **Customer segmentation:** capture the customer intelligence page only after authorized data is available. If unavailable, capture the honest empty state and label analysis pending.
- [ ] **Support intelligence:** show classification/summary behavior using fictional text or approved anonymized data; ensure no raw PII appears.
- [ ] **AI assistant:** show a policy response and citations; label checked-in policies as synthetic and the provider mode (mock/local) accurately.
- [ ] **API documentation:** capture Swagger at `http://127.0.0.1:8000/docs` with route list visible.
- [ ] **Test results:** capture terminal output from the exact commands run, with command and final pass/fail summary visible.
- [ ] **GitHub repository:** capture only after the owner creates the remote and explicitly approves publication. Do not imply a remote exists before then.

Suggested evidence captions should include date, configuration mode, whether the view uses actual trainer data, and any known limitations. Keep full screenshots unaltered; redact a copy if sensitive content is visible.
